# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

BAhelper is an Expo (React Native) app that compiles Blue Archive game data/tools: a home dashboard (Student of the Day drawing prompt, daily-reset countdown, upcoming birthdays, upcoming-banners strip), a searchable/filterable student roster with collection tracking, full student profile pages, and SCHALE tools (random roster generator, bond XP calculator, banner schedule with JP→Global predictions, inventory-minigame probability helper, raid score ↔ clear-time converter, student/account EXP calculator). Further ideas live in `ideas to implement.md` (gitignored but present locally).

## Commands

```bash
npm install          # install deps
npx expo start        # start dev server (or `npm run start`)
npm run android        # start with Android target
npm run ios            # start with iOS target
npm run web             # start with web target
npm run lint           # expo lint (eslint-config-expo flat config)
npx tsc --noEmit       # typecheck (app-example/ is excluded via tsconfig)
```

There is no test suite configured in this repo currently.

On Windows, `run me.txt` documents the two commands needed in a fresh PowerShell session:
```
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
npx expo start
```

## Architecture

- **Routing**: `expo-router` file-based routes under `app/`. `app/_layout.tsx` is the root `Stack` (wrapped in `UserDataProvider`); `app/(tabs)/_layout.tsx` defines the bottom tabs: Home (`index.tsx`), Students (`students/`), Tools (`tools/`), Settings (`settings/`). On iOS the tab bar is `NativeTabs` (`expo-router/unstable-native-tabs`, Liquid Glass on iOS 26); web/Android keep the JS `Tabs`. NativeTabs renders no headers, so Students/Tools/Settings are directories whose `_layout.tsx` is a one-screen `Stack` providing the header; shared header styling lives in `constants/navigation.ts` (`stackScreenOptions`, incl. `headerBackButtonDisplayMode: 'minimal'` so back buttons don't show the literal "(tabs)" group name). Non-tab stack routes: `app/student/[id].tsx` (student profile) and `app/tools/roster.tsx` / `app/tools/bond.tsx` / `app/tools/banners.tsx` / `app/tools/inventory.tsx` / `app/tools/raidscore.tsx` / `app/tools/exp.tsx`, all registered in the root Stack. Typed routes are enabled (`experiments.typedRoutes`) — the generated route types in `.expo/types/router.d.ts` refresh when the dev server starts, so a stale file can cause `tsc` route-string errors after adding/renaming routes.
- **Screens**:
  - `index.tsx` — dashboard: deterministic Student of the Day (seeded by "BA day", which flips at the in-game daily reset 19:00 UTC, see `getBADayNumber`), reset countdown, upcoming-birthdays strip (favorites highlighted), quick links.
  - `students.tsx` — roster grid with search, filter chips (school/damage/armor/role/position/weapon/stars/owned/favorites), sort modes, alt-grouping toggle. Long-press a tile to toggle "owned"; a bulk-edit mode (`bulk-toggle`) makes taps toggle owned instead of navigating and adds "Own shown"/"Clear shown" actions over the current filter result via `setOwnedMany` (RN-web `Alert` is a no-op, so the clear confirm falls back to `window.confirm` on web).
  - `student/[id].tsx` — full profile: portrait hero with school-icon watermark, then `SegmentedTabs` sub-tabs Overview (school life/combat/alts) · Stats · Skills · Lore (profile/weapon/bond gear/credits). Inactive tabs stay mounted behind `display:none` so `StatsSection`'s internal state survives switching. Header toggles for favorite/owned.
  - `tools/roster.tsx` — random 10-student SCHALE roster with per-slot lock/reroll, owned-only and 6-strikers+4-specials modes. `tools/bond.tsx` — bond XP calculator driven by `constants/bondXp.ts`.
  - `tools/raidscore.tsx` — Total Assault clear-time ↔ score converter driven by `constants/raidScore.ts` (formula + per-difficulty constants re-entered from jozsefsallai/ba-tools `src/lib/raids.ts`, MIT): `score = timeMult × (3600 − clearSecs) + difficultyScore + hpScore[duration]`; the last-edited field is the source, the other is derived.
  - `tools/exp.tsx` — student/account EXP calculator on generated `constants/expTables.ts`: student mode shows EXP + credit cost (7 credits/EXP) + greedy report mix (Superior→Novice); account mode estimates days at an AP/day rate (1 AP = 1 account EXP).
  - `tools/banners.tsx` — Global banner schedule from tracked `data/banners.json` (see banner pipeline below) via `utils/bannerUtils.ts` (`getBannerGroups` merges same-window/same-type runs into display cards; the permanent "Archive" gacha is filtered by its >60-day duration): running → confirmed upcoming → predicted (dashed cards, `est.` tag). The home dashboard shows the first 6 groups as a strip.
  - `tools/inventory.tsx` — inventory-management minigame helper: presets in `constants/inventoryPresets.ts` (9×5 grid, per-event rounds of 3 items, shapes re-entered from jozsefsallai/ba-tools which is MIT), Monte Carlo engine in `utils/inventorySim.ts` (seeded PRNG per board state so results are stable across re-renders; conditions on revealed *item* cells per type as well as misses, so found items need no manual bookkeeping; returns `null` for contradictory boards → UI warning). Verified cell-by-cell against Joe's live tool (≤1.4pp deviation on the shared default config).
- **State**: `context/UserDataContext.tsx` (`useUserData()`) holds owned/favorite student ID sets and app settings (`dailyIncludeAlts`, `showDailyImage`), persisted via AsyncStorage (`utils/storage.ts`, keys `bahelper:*`). On web this backs onto localStorage.
- **Remote data sync**: `context/DataSyncContext.tsx` (`useDataSync()`) + `utils/dataSync.ts`. Tracked `data/manifest.json` holds a `dataVersion` (unix ms) that the scrapers bump on every data write; the app hydrates cached downloads from AsyncStorage at launch (provider holds the first frame), then background-checks `raw.githubusercontent.com/Ian63271/BAhelper/master/data/manifest.json` and downloads/validates/applies `students.json` + `banners.json` only when the remote version is NEWER than the active one (so a stale/unpushed remote can never downgrade the bundle). Applying mutates `allStudents`/`studentById`/`bannerData` **in place**; screens that derive lists from them must include `activeVersion` from `useDataSync()` in their memo deps (home, students roster, banners do). Settings has a "Game Data" section (check for updates, delete downloaded data — the bundled snapshot is restored without restart). **Sync only works once the repo is pushed**; until then checks report unreachable and the app runs on the bundle.
- **Student image fallback**: `utils/studentImages.ts` (`studentIconSource`/`studentPortraitSource`) — bundled `imageMap` art first, falling back to `schaledb.com/images/student/{icon,portrait}/{id}.webp` for students that arrived via a remote data update. Use these instead of indexing `studentIcons`/`studentPortraits` directly for student art.
- **Daily fan art**: `utils/dailyImage.ts` + `components/DailyImageCard.tsx` (home dashboard, under Student of the Day, toggle in Settings). Source is **safebooru.org**'s anonymous gelbooru-style JSON API (danbooru.donmai.us is Cloudflare-challenge-walled and gelbooru.com needs an API key — both checked 2026-07). Tag scheme `aru_(new_year)_(blue_archive)` derives from the student name; multi-word collab names (Hatsune Miku etc.) drop the suffix; empty alt results retry the base tag. Queries append `-cosplay -photo_(medium)` — cosplay photos carry the character tag via the `X_(cosplay)` implication without depicting the character (the specific `X_(cosplay)` tag is too inconsistently applied to exclude instead). Zero-result queries return an **empty body**, not `[]` — `fetchPosts` must not parse blindly. A failed fetch sets a distinct `error` state that retries on tab focus / app foreground (an `empty` day is cached and final). Pick is seeded by BA day + student id and cached per day (`bahelper:dailyImage`). The API sends no CORS headers, so on web the card silently hides — mock the route in Playwright to test it (see `scratchpad` smoke scripts pattern: `context.route` fulfilling safebooru + raw.githubusercontent).
- **Domain helpers**: `utils/studentUtils.ts` — the single import point for student data (`allStudents`, `studentById`), plus daily-pick logic, alt grouping (`getBaseName`/`collapseAlts`/`getAltFamily` — alts are detected by the `" ("` name suffix), birthday math, and roster filter/sort helpers.
- **Design tokens**: `constants/theme.ts` — BA-flavored palette, spacing/radius scales, damage/armor color+label maps (in-game convention: a damage type is strong vs the armor type sharing its color), school display names, adaptation letter grades, reset hour constant.
- **Data model**: `types/students.ts` defines the `Students` interface — a superset schema modeled after SchaleDB's fields; most fields optional. Notes: `mood` = [Urban, Outdoor, Indoor] adaptation values 0–4 (D→S); `limited` = per-region status array (1=Limited, 2=Event, 3=Fes; other values mean permanent); `stats` holds raw Lv1/Lv100 stat pairs plus fixed points; `skills` holds trimmed skill records (ex/public/gearPublic/passive/weaponPassive/extraPassive — EX levels 1–5, others 1–10).
- **Stats & skills rendering**: `utils/statCalc.ts` replicates SchaleDB's stat formula exactly (level lerp with `.toFixed(4)` truncations + cumulative star-grade transcendence multipliers for ATK/HP/heal; DEF doesn't star-scale; unique-weapon bonuses are flat `round(lerp)` additions to ATK/HP/heal, `Standard` growth truncates the scale) — don't "simplify" the rounding chain or parity breaks. Caps live there too: student level 90, UE stars 1–4 with weapon level cap `20 + 10×star` (UE60); UE selection implies a 5★ character. Buff modifiers (gear/bond/talent/weapon) go through the SchaleDB `CharacterStats` pipeline: `addBuff` accumulates per-stat flats and basis-point coefficients (`_Base`/`_Coefficient` suffix on the stat name; plain names are flat), and `combineStat` computes `round(((base + flat) * (1 + coeff)).toFixed(4))` — percent gear multiplies AFTER weapon/bond/talent flats. `calcBondStats` (bond gains stop at rank 50; the student's OWN applied bond is additionally capped by star grade via `BOND_STAR_CAP` `[10,10,20,20,50]`, while alt-family bond contributions are uncapped — SchaleDB stat-preview parity), `calcPotentialStat` (0.2%/level of the lerped base with no transcendence/ceil, max 25 per HP/ATK/Heal track) and `addEquipmentBuffs` (tiers T1–T10 from `constants/equipmentStats.ts`, generated) feed it. `utils/skillText.ts` parses skill descriptions (`<?N>` per-level parameters, `<b|d|c|s:Key>` buff tags resolved via `constants/buffLabels.ts`, colored per `buffTagColors` in theme) into typed segments rendered as nested `<Text>`. `<kb:N>` knockback tags are resolved to distances at scrape time in `scrapper.js`.
- **Student data pipeline (local-only, gitignored dev tooling)**: `data/scrapper.js` (fetches SchaleDB `students.min.json` → `data/students.json`), `data/imagescrapper.js` / `data/iconscrapper.js` (portraits/icons into `assets/images/students|icons`), `data/schooliconscrapper.js` (school icons into `assets/images/schools`, pulled from the SchaleDB GitHub repo since the SPA swallows direct image paths), `data/skilliconscrapper.js` (unique skill icons into `assets/images/skills`, preferring the GitHub repo with a schaledb.com fallback for icons the repo lags on), `data/equipmentscrapper.js` (regenerates `constants/equipmentStats.ts` from SchaleDB's `equipment.min.json` — gear Id scheme is `categoryBase + tier - 1`; filtering by `Category` alone over-matches blueprints), `data/localizationscrapper.js` (regenerates `constants/clubLabels.ts` and `constants/buffLabels.ts` from SchaleDB's `localization.min.json` — student records carry internal club keys like `Kohshinjo68` and skill descs carry buff keys like `<b:AttackPower>` that need these maps for display names), `data/equipmenticonscrapper.js` (gear item icons for all 9 categories × T1–T10 into `assets/images/equipment/{Category}_T{tier}.webp`), `data/uiiconscrapper.js` (adaptation emote faces `Ingame_Emo_Adaptresult{D..SS}` and `Terrain_{Street,Outdoor,Indoor}` icons into `assets/images/ui`), `data/expscrapper.js` (regenerates `constants/expTables.ts` — student/account per-level EXP from github.com/electricgoat/ba-data branch `global` (the aizawey479 mirror is stale at Lv85); report EXP values and the 7-credits-per-EXP price are cross-checked against bluearchive.wiki's Character_Exp_table page), and `data/imagemap.js` (regenerates `types/imageMap.ts`).
  - **Banner pipeline**: `data/bannerscrapper.js` (gitignored) → tracked `data/banners.json` (`types/banners.ts`; all timestamps unix **ms**). Sources: bluearchive.wiki MediaWiki API at `/w/api.php` (NOT `/api.php`; needs a browser User-Agent), yearly subpages `Banner_List/Banners_of_YYYY` (JP) and `Banner_List_(Global)/Banners_of_YYYY` (GL) holding `{{Banner}}` templates. GL rows' `CrossregionId` = the JP run's wiki `Id` (the JP↔GL join; don't join on `Code` — reruns can differ). Wiki rateup names are translated to SchaleDB names in `toSchaleName` (Arisu→Aris, Sportswear→Track, Battle→Armed, fullwidth ＊ etc. — unmatched names are logged, add to the alias maps). Predicted Global window = JP window + median offset of the 6 most recent matched pairs (132 days as of 2026-07). SchaleDB `config.min.json` `CurrentGacha` (unix **seconds**) and `api.ennead.cc/buruaka/banner` (ms) are console cross-checks only; SchaleDB's config can lag a banner rotation by a day.
  - `types/imageMap.ts` (tracked) holds static `require(...)` maps: `studentPortraits`, `studentHalos`, `studentIcons` (keyed by student ID), `schoolIcons` (keyed by school name), `skillIcons` (keyed by SchaleDB icon name, e.g. `SKILLICON_SHIROKO_EXSKILL`), `equipmentIcons` (keyed `"{Category}_T{tier}"`), `adaptationEmotes` (keyed by letter grade `D`–`SS`) and `terrainIcons` (keyed `Street`/`Outdoor`/`Indoor` — white game-UI glyphs, must be tinted on light backgrounds via expo-image `tintColor`). Metro needs static requires — never load images by dynamic path.
  - **Halo images have no public source** (not on SchaleDB or the wikis; only in game asset bundles), so `studentHalos` is empty and the UI doesn't rely on it. Schools `WildHunt`, `Highlander`, `Sakugawa` have no icon either — UI must handle a missing `schoolIcons[school]`.
  - `data/students.json` IS tracked (runtime data source); `data/students.json.old` is a gitignored backup.
- **`components/`**: `ScreenContainer`, `SectionCard`, `StudentIconTile` (memoized grid tile, damage-type colored rim), `FilterChip`, `TypePill` (damage/armor pills), `StatBadge` (label-over-value block), `Button`, `ImageViewer`, `LevelControl` (stepper with min/MAX chips plus a tap-to-type numeric `TextInput` for the value — draft while focused, clamped commit on blur/submit, `${testID}-input` — a `valuePrefix` prop — `'Lv. '` default — and an optional `icon` image shown before the label, used for student faces on bond rows), `SegmentedTabs` (pill segmented control, used for profile sub-tabs and EXP calculator modes), `GearTierControl` (SchaleDB-style gear picker: trigger shows the equipped item's icon + tier, opens a modal T0–T10 list with the real item art from `equipmentIcons`), `StatsSection` (level/star/UE-driven stat grid — gold char stars plus blue weapon stars — plus a collapsible "Gear · Bond · Talent" area: 3 gear tier pickers T0–T10, bond rank 1–100 with one extra row per playable alt (`hasAlts` = SchaleDB `FavorAlts`, each alt applies its own favor table at its own rank — note Shiroko*Terror is bond-separate from Shiroko despite the name), 3 talent steppers 0–25, bond-gear T2 toggle; `ueStars` is a controlled prop owned by `app/student/[id].tsx` so the Combat card's mood row can render the UE 3★+ terrain boost as base → boosted, e.g. S → SS), `SkillCard` + `SkillsSection` (EX/Basic/Enhanced/Sub with Bond Gear / UW 2★ variant toggles).
- **`assets/` is entirely gitignored** — a fresh clone must run the pipeline scripts (`scrapper.js`, `imagescrapper.js`, `iconscrapper.js`, `schooliconscrapper.js`, `skilliconscrapper.js`, `equipmenticonscrapper.js`, `uiiconscrapper.js`, then `imagemap.js`; plus `localizationscrapper.js` after a data refresh) to populate images and regenerate labels.
- **Path alias**: `@/*` maps to the repo root (see `tsconfig.json`).
- **`app-example/`** is the original `create-expo-app` template output, kept for reference only (gitignored, excluded from tsconfig, not part of the running app).
